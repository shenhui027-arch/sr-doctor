# 使用指南

界面顶部是一条工作流：**查询 → 诊断 → 建议 → 对比**，之后是 v1.0 的监控视图：**趋势、告警、治理**。右上角可以连接 StarRocks、切换中英文。

## 读懂结论的几条约定

整个产品都遵守这几条，读结果时请记住：

- **缺失不等于 0**：指标缺失、解析失败、部分可用、溢出、版本未知，都会单独标出，绝不当作 `0`。
- **只画能证明的结构**：执行结构里的边分为显式、已验证推导、部分三种；无法证明的关系不画，也不会伪造成一棵树。
- **不打健康分**：严重度、置信度、证据完整度与限制分开展示，不合成一个分数；只看延迟也不会判定查询“健康”或“不健康”。
- **说不知道**：样本不足、版本或规则变化、采集缺口时，显示“样本不足”“暂不可比”“部分”，不硬给结论。

## 获取 Profile

### 离线导入

首页或 **查询** 页点 **导入 Profile**，选择 JSON 或文本格式的 Profile 文件（不超过 34 MiB）。原文只在服务进程内存中分析，不写入磁盘、日志或遥测。

从 StarRocks 导出 Profile 的常见方式：

```sql
-- 开启 Profile 后执行目标 SQL，再取最近一次的 Profile
SET enable_profile = true;
SELECT get_query_profile(last_query_id());
```

### 连接 StarRocks

点右上角 **连接**，填写 FE 的主机、端口（默认 `9030`）、用户名、口令。连接成功后，**查询** 页有四种选法：

| 选法 | 用途 |
|---|---|
| **审计历史** | 读审计日志（需要 AuditLoader）。默认打开 **概览**（见下节）；**同类 SQL** 按官方 digest 归并，看频次与累计消耗，没有 digest 时使用非官方指纹并标注；也可以查看 **相似 SQL** 聚类和 **单次执行** |
| **Profile 列表** | FE 上已有的 Profile，直接拉取诊断 |
| **运行中** | 正在执行的查询，可以拉取运行中快照 |
| **SQL 工作区** | 粘贴一条 SQL，看固定的 `EXPLAIN COSTS` 计划图；或者开启“运行时 Top”执行它，再分析这次执行的 Profile |

本工具自己发出的语句，默认在列表里隐藏，并显示隐藏了多少条。

### 审计概览

审计历史的默认视图，回答“这段时间集群在忙什么、慢在哪里”。

- **所选时间窗 · 审计表**：对筛选条件下的审计记录做一次有界聚合读取（与卡片、同类 SQL 同一口径，已去重）。
  - **卡片**：执行次数、失败与占比、耗时 P50/P95/P99、CPU 累计（不是墙钟时间）、扫描量累计、执行中峰值。
  - **趋势图**：可切换查询量与失败、耗时分位（对数轴）、扫描量、CPU、内存峰值、排队时间；时间粒度默认自动（1 小时窗为 1 分钟，24 小时为 15 分钟），也可以手选。最近几分钟的时段标“可能尚未全部落库”。
  - **所选时段**：点柱子或用“上一段 / 下一段”切换，可以直接看该时段的单次执行或同类 SQL。
  - **耗时分布、失败拆分、负载构成**：负载构成按用户、数据库、资源组、Catalog 分别给出按累计耗时、次数、失败的精确 Top；文本值可一键加为筛选条件。
  - 分位数用 StarRocks 的 `PERCENTILE_DISC`（取排序后第 ⌈p·(n−1)⌉ 位的实际值，不插值）；为空、重复行不一致的记录单独成行，不当作 0。
- **30 天 · 历史库**：读本机历史库的小时聚合，不再查询审计表。
  - 每日柱图：已采集、部分采集、未采集分开画；StarRocks 版本或规则变化前的日子灰底，与之后不比较。
  - 星期 × 小时热力图（只用完整采集的小时）与本周对上周（部分采集时不比较，上周为 0 只给绝对变化）。
  - 只画可相加的量；分位数不能由小时聚合合成，这里不提供。远端集群默认不采集，此时会说明原因。

> **运行时 Top** 必须逐次显式开启：只接受一条 `SELECT`/`WITH`，在单独的短会话里开启 Profile，超时 10 秒，丢弃结果行，不自动重试。它会真实执行这条 SQL，请只在可以承受这次负载的集群上使用。

## 诊断

选中查询后点 **拉取 Profile 并诊断**（导入的 Profile 会直接进入诊断）。诊断页分三块：

- **执行结构图**：Fragment 与算子拓扑，显示每个算子占算子总耗时的比例；**定位最耗时节点**一键跳到耗时最高的算子，点算子查看它的指标。
- **发现项**：按严重度排列，每条包含：
  - **证据**：触发结论的指标与数值，可跳转到算子；
  - **置信度**与**限制**：这条结论在哪些情况下可能不成立；
  - **建议**：下一步该看什么。
- **算子与指标 / 原始 Profile**：所有指标都标明单位与解析状态，并能追溯到原文的位置。

页面顶部会显示 StarRocks 版本与所用的版本包：3.5.14 显示“版本包匹配”，其他已支持版本（3.1 及以后）显示“3.5.14 基线 + 某版本线差异”。2.5、3.0 和审计范围外的版本提示“无版本包”，不会套用最近版本的规则。

## 建议

**建议** 页把发现项整理成可执行的排查步骤。每条建议都包含：

- 关联的发现项、算子与原文证据；
- 排查步骤与验证计划；
- 预期方向：哪些指标应该往哪个方向变化。

本产品不会自动修改 SQL 或参数，也不预估“能提升百分之几”。

## 前后对比

在 StarRocks 上按建议改完并重跑之后：

1. 在当前诊断上点 **设为基线并对比**，或在 Profile 列表里选两条执行；
2. 选择改动后的那次执行作为候选；
3. 查看结果：
   - **实测变化**以区间表示（文本 Profile 的数值本身有精度区间）；
   - 基线为 `0` 时只给绝对变化，不给百分比；
   - 版本或指标语义不同的项标“不可比较”；
   - 发现项的变化分为已解决、新增、持续；依据部分证据判定的条目会单独标注。

对比结果可以 **导出对比报告**，报告已脱敏。

## 趋势

> 需要历史库，以及正在进行的后台采集。远端集群默认不采集，见 [部署指南](deployment.md#远端集群的后台采集)。

- **模板趋势**：按 SQL 模板展示每小时的中位耗时与基线带。样本不足的小时显示“样本不足”，没有采集的小时留空，不插值。
- **回归判定**：用基线中位数与 MAD 判定；StarRocks 版本、版本包或规则集变化前后的数据标“暂不可比”。
- **采集与历史**：查看采集水位、每次读取的预算、近 24 小时覆盖率，可以暂停或恢复采集，也可以清空本机历史（不会改动 StarRocks）。

## 告警

告警页顶部按 **SQL 性能回归** 与 **导入** 切换，导航角标是两类新告警之和。

SQL 性能回归告警只来自回归判定。每条告警分开展示严重度、置信度与证据完整度，可以 **查看趋势与代表执行**。当前阈值标为“规则试运行中”，需要在真实业务数据上校准（G2）。

### 导入告警

导入告警由后台采集存下的导入历史（见“导入 › 历史”）在每轮采集后评估，不额外读取 StarRocks。规则处于试运行，阈值尚未用真实业务校准：

| 规则 | 触发 | 严重度 | 自动解决 |
|---|---|---|---|
| Routine Load 暂停 | 作业最近一次快照为 PAUSED | 高 | 回到 RUNNING / NEED_SCHEDULE |
| 停止或取消 | 快照之间观察到作业变为 STOPPED / CANCELLED（首次看到就已结束的作业不报） | 中 | 作业从完整快照中消失 |
| 积压持续增长 | 运行中，最近 3 个完整小时的最大分区积压（最新位置 − 已消费位置，按消息条数）逐小时上升，最新 ≥ 10,000 条且 ≥ 3 小时前的 2 倍 | 中；≥ 100 万条为高 | 不再上升或低于 10,000 条 |
| 失败率突增 | 同表同类型（Stream Load / INSERT / Broker Load），最近 3 小时 ≥ 20 次、前 7 天 ≥ 100 次；当前 ≥ 5%，高出基线 ≥ 5 个百分点且 ≥ 3 倍 | 中；≥ 20% 为高 | 回到基线 + 2.5 个百分点以内 |
| 过滤率突增 | 最近 3 小时输入 ≥ 1,000 行、基线 ≥ 10,000 行；当前 ≥ 1%，高出基线 ≥ 1 个百分点且 ≥ 3 倍；计数没有未知 | 中；≥ 10% 为高 | 回到基线 + 0.5 个百分点以内 |

- 样本不足、最近 3 小时里有未采集或部分采集的小时、基线与当前的 StarRocks 版本或统计规则不同时，不判定：不触发，也不解决。
- 同一个作业或同一张表的同一类型只保留一条告警；标记已确认、静默 24 小时、重新打开与 SQL 告警相同。类别切换上的数字是新告警（未确认）条数。每种状态先列最近 500 条，更多的可以在该状态下继续显示。
- 每条告警写明它的证据所在的 StarRocks 版本与统计规则；积压需要最近 4 个小时都有完整快照且版本一致。
- 详情里有当前窗口与基线的计数、每小时积压，以及 Routine Load 的暂停原因（只在应用内显示）；可以直接跳到“导入 › 历史”的对应表、作业或错误日志。
- SR Doctor 只读，不会恢复或修改作业。

### 告警通知

告警页有三个标签：**告警列表**、**通知渠道**、**投递记录**。除了应用内角标，新告警还可以发到邮件、飞书、钉钉和短信（阿里云、腾讯云）。

- **渠道**是“怎么发”：邮件的 SMTP 服务器、短信平台的 AccessKey 与已审核的签名、模板；飞书和钉钉没有渠道级设置。
- **发送对象**是“发给谁”：收件人邮箱、群机器人（各自的 Webhook 与签名密钥）、手机号。每个渠道最多 20 个，每个对象可以单独启用、单独测试，并单独设置接收严重度（“中及以上”或“仅高”）。
- 点渠道卡片打开设置弹窗，在里面填渠道设置、增删改发送对象；页面下方的总表列出全部发送对象和各自的最近投递结果。
- 添加或修改发送对象时可以 **先发一条测试**，不保存也能试。

发送规则（所有渠道共用）：

- 只在 **新告警** 出现时发，包括静默结束后仍在回归的告警；持续回归不重复发，静默中的告警不发。可选在告警恢复到基线带时再发一条“已解决”（短信不发）。
- 同一次采集评估产生的多条告警，每个发送对象合并成一条消息。
- 消息只写集群、模板指纹、严重度、置信度和耗时中位数变化，不含 SQL 字面量、Profile 或口令；可以选择附带脱敏后的 SQL 模板（短信始终不带）。填了“SR Doctor 访问地址”时，消息里带“查看告警”链接。
- 导入告警与 SQL 告警在同一轮评估后合并发送，每条写规则、作业或表、当前值与基线、时间窗口，不含错误日志原文或暂停原因原文；短信只有条数与最高严重度。

各渠道要准备的东西：

| 渠道 | 需要 |
|---|---|
| 邮件 | SMTP 主机、端口、加密方式（SSL/TLS 或 STARTTLS，始终校验证书；也可以选“不加密”，口令与内容会明文传输）、发件人，需要登录时填用户名和口令（建议用邮箱的授权码） |
| 飞书 | 群设置 › 群机器人 › 添加自定义机器人，复制 Webhook；开启“签名校验”时一并填签名密钥。只接受 `open.feishu.cn`、`open.larksuite.com` 的地址 |
| 钉钉 | 群设置 › 机器人 › 添加机器人 › 自定义，安全设置选“加签”，复制 Webhook（含 access_token）与 `SEC` 开头的密钥。只接受 `oapi.dingtalk.com` 的地址 |
| 阿里云短信 | 建议用只有短信发送权限的 RAM 子账号的 AccessKey；控制台审核通过的签名和模板，模板变量为 `${cluster}`、`${count}`、`${level}` |
| 腾讯云短信 | 建议用只有短信发送权限的子用户的 SecretId/SecretKey；SdkAppId、审核通过的签名和模板，模板按顺序取 `{1}` 集群、`{2}` 条数、`{3}` 严重度 |

短信按条计费，每个短信渠道默认每小时最多 10 条（可在渠道设置里调整，1–100），超出的跳过并在投递记录里标“超出频率上限”，告警仍保留在应用内。

**投递记录** 列出每次发送：时间、渠道与发送对象、内容、结果（成功、失败、等待重试、已跳过）、尝试次数和错误类别。发送超时 10 秒；网络类失败按 1、5、30 分钟重试，共 4 次。记录只存错误类别和平台返回码，不存消息正文和密钥，保留 30 天。

> 告警来自后台采集。远端集群在 G1 生产只读试点通过、设置 `DOCTOR_COLLECTION_ALLOW_REMOTE=after-g1` 之前不采集，因此也不会产生告警和通知。飞书、钉钉、阿里云和腾讯云的真实发送尚待用真实账号验证。

升级后，旧规则产生的告警会标为 **规则已变更**：新规则无法与它们比较，它们不会自动解决。列表上方会提示数量，点 **全部标为已解决** 即可一次清理；清理后仍可逐条重新打开。

## 导入

顶栏的 **导入** 需要先连接 StarRocks。**概览**、**Routine Load**、**导入记录** 实时读取 StarRocks 的 `information_schema`，打开期间每 30 秒刷新一次；**历史** 读本机历史库里后台采集存下的内容。

- **概览**（默认打开）：顶部按类型切换 **全部 / Stream Load / INSERT / Routine Load**（有 Broker Load 记录时另有 **Broker Load**），每类只显示 StarRocks 为它提供的指标，口径不混算；可以选择是否包含系统任务。
  - **全部**：导入次数、失败、过滤行、Routine Load 作业与最大分区积压五张指标卡；每小时导入次数按类型堆叠，有失败的小时顶端标红；**按类型对比**表列出各类的次数、失败、写入行、过滤行与总耗时 P95；过滤行最多的表。
  - 每小时的柱子按创建时间画 72 小时，以最新一条记录所在的小时结尾。早于最早一条记录的时段画成灰色，表示 StarRocks 已经不保留，不是“没有导入”；斜纹柱是可能不完整的小时。点一根柱子（或用左右方向键）看这一小时的数字，再点 **查看这一小时的导入记录**。
  - **Stream Load**：接收数据量（`SCAN_BYTES`，即客户端发来的字节）与写入行；每小时次数、失败与接收数据量；取事务、规划、接收数据三段毫秒耗时的分布与 P50 / P95（样本不少于 20 条）；失败原因（过滤行超限、超时、Label 已存在、其他）；总耗时与发布等待（提交到完成）的 P95，以及用了超时设置 80% 以上的导入；按表与按客户端 IP、用户的统计。接收数据耗时在测试环境里一直是 0，是否与客户端返回的 `ReadDataTimeMs` 同口径尚待核实。
  - **INSERT** 与 **Broker Load**：写入行、扫描行与扫描数据量；总耗时分布（秒级）；最慢的 8 次，拆成执行（创建到提交）与发布（提交到完成）两段，并标出占超时设置的比例；按 `ERROR_MSG` 里的 `type` 归类的失败原因；进行中的导入；按目标表的统计与优先级。INSERT 的开始加载时间就是创建时间，没有“排队”这一段；Broker Load 加载前有排队与准备，这段时间计入总耗时，最慢列表里那一段标为“提交前（含排队）”。
  - **Routine Load**：每个作业的状态、当前与期望任务数、平均导入速率与接收速率、累计导入行、错误行与错误率、提交与中止的任务数、平均任务执行时间、最大积压和最新消费消息的时间；每小时提交的任务与导入行；任务耗时分布（秒级）；分区积压 Top 10；暂停或已结束的作业及原因。作业指标是作业创建以来的累计值，速率是累计平均，不是当前速率；自动暂停按最近一段窗口内的错误行判断，这个窗口 StarRocks 不对外提供，所以不估算“离自动暂停还差多少”。3.2 没有积压、错误日志和任务记录，只显示作业累计值与状态。
  - 时间点都只到秒，不足 1 秒的耗时记为 0 秒；只有 Stream Load 有毫秒级阶段耗时，而且要到提交时才测出，进行中的 Stream Load 与 Routine Load 任务都显示为未知，不计入分布。某小时的导入都没有报告数据量时，数据量折线在这里断开，不画成 0。
- **查询 → 审计历史 → 概览** 里也有一张 **导入** 卡片：数字与小柱图来自同一份读取，显示的是 StarRocks 当前保留的导入（最近 3 天、约 1000 条），**不随审计概览的时间窗变化**，因为导入记录只有秒级的 FE 本地时间。卡片读取失败不影响审计概览；点 **打开导入概览** 或暂停的作业可以直接跳过去。

- **Routine Load**：每个作业的状态、最大分区积压、导入速率、错误行与总行。点一行，右侧显示状态变化原因（例如超过 `max_error_number` 自动暂停）、累计统计、容错设置，以及每个分区的已消费位置、最新位置、积压和消费到的消息时间。积压来自 `OFFSET_LAG`，需要 3.3 及以上。SR Doctor 只读，不提供暂停、恢复或修改作业。
- **导入记录**：Stream Load、Broker Load、INSERT，以及 Routine Load 的每个提交任务。可以按类型、结果、库表筛选；默认隐藏统计信息收集和审计日志产生的系统任务。
  - 取事务、规划、接收数据三段是 StarRocks 记录的毫秒值；写数据、提交发布两段 StarRocks 不记录，总耗时由开始与完成时间相减，只精确到秒。
  - 时间按 FE 的时区显示，不做换算。
  - StarRocks 只在 FE 内存里保留最近 3 天、每类最多约 1000 条。Stream Load（含 Routine Load 的任务）一旦超过 `stream_load_task_keep_max_num`（默认 1000），FE 会一次清掉所有已结束的记录，可见条数可能骤降到个位数（3.5.14 实测：连续 1000 次后只剩最后 3 次）。页面上方会给出当前能看到的最早一条，概览里更早的小时标为“未知”或“可能不完整”。
- **错误日志**：有过滤行的导入可以点 **错误日志**。内容来自 StarRocks 的 `information_schema.load_tracking_logs`，与 Stream Load 返回的 ErrorURL 相同，SR Doctor 不直接访问 BE 的 8040 端口。
  - 每次导入 StarRocks 最多记录约 50 行错误，每行只报第一个错误；原因分布按这些样本统计。
  - “非空列为 NULL”“超出分区”两类给出的是转换后的值，不是原始文本。
  - BE 默认 48 小时后删除错误日志，删除后页面会说明“已被清理”。
  - 原始行是业务数据。这里显示的是打开时实时读取的内容；后台采集另会把有过滤行的导入的错误日志保存一份（见下面的 **历史**）。
- **历史**：后台采集任务（与审计历史共用，每 5 分钟一次，见 [部署指南](deployment.md#远端集群的后台采集)）把已结束的导入按完成时间存进本机历史库，保留 30 天。可以选 7 天或 30 天、按类型和库表筛选。
  - **统计**：已结束的导入、失败、写入行、过滤行与已保存的错误日志五张指标卡；每天导入次数按类型堆叠，下面一行是采集覆盖（完整、部分、未采集）；每天的失败率与过滤率；按表汇总，带“主要过滤原因”（来自保存的错误日志样本，不代表全部过滤行），原因在最近 3 天才第一次出现时标“新出现”。日期按 UTC 日划分。
  - 只统计已结束的导入，进行中的在 **概览** 里看。没连接或暂停采集的时段是“未采集”，不补数据；读取时 StarRocks 已经清掉了这段的记录（Stream Load 超过 1000 条时整批清理），或读到 2000 条上限，这一小时标为“部分”。StarRocks 版本变化前后单独成段，不跨段比较。
  - 选 **Routine Load** 显示作业：每个作业 30 天的状态条（运行、暂停、已取消、未采集）、暂停次数、导入行与错误行、提交与中止的任务；点作业看每小时的最大分区积压（暂停期间加底色）、状态变化与原因、每天的导入行与错误行。增量是相邻两次快照累计值之差；作业重建（累计值变小）或两次快照相隔太久时，这一段记为未知，不计入。积压只在快照时刻取值。
  - **错误日志**：有过滤行的导入结束后，下一轮采集按 `job_id` 读一次 `load_tracking_logs`（每轮最多 5 份，每份最多 50 行、64 KB，单行超过 4 KB 截断），保存原因计数与原文。列表只显示原因与条数，点 **查看** 才显示原文。保留 30 天，原文总量超过 50 MB 时先删最旧的；读取前 StarRocks 已删除（48 小时）的标“读取前已被清理”。
  - 错误原文按约定**明文**保存在本机历史库：能登录 SR Doctor 的人都能看到所有库的原文，复制或用 `./deploy.sh backup` 备份历史库时原文随之带走；原文不进日志、告警通知和导出。在 **趋势 › 采集与历史** 里 **清空历史** 会一并删除。

> 3.5.14 上，没有任何授权的账号也能读到所有库的导入记录与错误日志，这是 StarRocks 的行为；SR Doctor 显示 StarRocks 返回的内容，不另做库权限过滤。

## 治理

把需要跟进的告警或模板放进 **治理队列**：

1. **新建 → 已分诊**：确认问题，可以钉住一份基线分析快照（快照里的字面量同样脱敏）；
2. **处理中**：在本工具之外修改 SQL、表结构或参数，并在治理项里记录做了什么；
3. **待验证**：重跑后用前后对比验证；
4. **已关闭**：只有验证结果确认改善才会自动关闭，不能手动关闭。

确认不需要处理的项可以标为 **不处理**，它会离开待办，但不会算作“已改善”。

## 安全提示

- 连接口令只在服务进程内存里，断开、空闲 15 分钟或服务重启后删除。
- 建议为本工具创建只读账号，只授予读取审计表和 Profile 所需的权限。
- 明文连接时，口令与 SQL 在网络上不加密；跨不可信网络请选 TLS verify-full。
- 告警通知的密钥加密后存进历史库，主密钥默认在同目录的 `secret.key`；需要分开保管时见 [配置参考](configuration.md#告警通知的主密钥)。

# v0.1 实现与 Candidate 验收矩阵

状态：Approved Phase 0C acceptance baseline / 执行：已实现，随 v0.7.0 冻结；生产连接安全仍为 `INCONCLUSIVE`

每项通过必须附命令、exit code、test count、fixture/input SHA-256、算法版本和失败边界。`存在代码`、`README 声明`、`页面可打开`均不等于通过。

## 1. 支持范围

| 输入/能力 | v0.1 | 验收要求 |
|---|---|---|
| JSON Profile | 必须 | 3.5.14 synthetic corpus + Partial IR + graph quality |
| Text Profile | 必须 | 与等价 JSON 的 canonical facts 对齐 |
| Doctor Findings | 必须 | typed inputs/evidence/confidence/limitations/rule trace |
| Analysis/Comparison 报告导出 | 必须 | public snapshot + receipts/manifest/hash；默认无原文/SQL/路径且可离线校验 |
| 两份 Profile Compare | 必须 | compatibility/structure/runtime metrics/findings/validation context |
| StarRocks Connection | 必须 | 短期 credential session、version/capability/TLS、Connected Read-only allowlist |
| Audit / Profile browser | 必须 | AuditLoader allowlist query；不可用时显式降级 ProfileList；按 query ID 拉 Profile |
| Explain / Plan Compare | 必须 | 目标 FE 生成；Explain/Explain 只比结构，Profile/Explain runtime 不可比 |
| SQL execution / EXPLAIN ANALYZE | 仅 Runtime Top 受限单条查询；其余禁止 | 前端显式模式开关；SELECT/WITH、单语句、固定超时、丢弃结果、同次 Profile；`EXPLAIN ANALYZE` 与写入在远端调用前拒绝 |
| Plan Advisor guide | 必须 read-only | 官方来源/版本/限制可见；无 ADD/DROP/TRUNCATE |
| 自动聚类 / Quality Monitor | 后置 | digest 仅筛选/分组，无长期采集/趋势/告警/治理 |
| 自动 SQL/参数变更 | 不支持 | recommendation 仅含人工实验/验证步骤 |

## 2. Contract / corpus 门禁

| ID | 通过条件 |
|---|---|
| C-01 | IR/Metric/Graph/Finding/Comparison/Connection/Explain/OptimizationContext/Error schema 生成 Rust/TypeScript type，canonical JSON round-trip/hash 一致 |

## 3. Parser

| ID | 通过条件 |
|---|---|
| M-01 | `500ms/us/ns`、`1m2ms` 最长匹配正确；`μs(U+03BC)/µs(U+00B5)` 在 3.5.14 strict pack 下稳定拒绝 |
| M-02 | `1m30s`、`1h30m`、`2s345ms`、合法小数正确 |
| M-03 | 前后缀、指数/符号、重复/逆序单位、非最后小数被稳定拒绝 |
| M-04 | count K/M/B 按 1000；3.5.14 bytes `KB/MB/GB/TB` 按 1024；`KiB/MiB/...` 拒绝；ratio/percent canonical 值与单位冻结 |
| M-05 | parenthetical raw count 一致性、unitless allow/deny policy 通过 |
| M-06 | parser 的 missing/invalid/partial/overflow/exact 与 exact zero 序列化不同，无默认 0 |
| M-07 | i64 boundary、乘法/加法 overflow、non-integral canonical 通过 |
| M-08 | strict trailing input invalid；compat partial 无 canonical value且不得进入规则/Compare |
| M-09 | 固定 seed bounded property tests 无 panic；无无界 fuzz/灾难性 regex |
| M-10 | `parse_state=exact` 与 fidelity 分离；Text time/bytes/count 的 exact/rounded/truncated/interval 端点包含性、HALF_UP tie 与 bounds 按官方 formatter golden 传播 |

## 4. IR、版本与图

| ID | 通过条件 |
|---|---|
| I-01 | JSON/Text 等价 fixture 的 canonical fact subset 与 facts_hash 一致；source/input/provenance 不同使完整 Report/analysis_key 不要求相同，有损 Text 与 raw JSON 不伪称 exact 等价 |
| I-02 | 每个核心值有 source ref、parse/semantic state、unit、registry/pack version；semantic unavailable 与 parser 各态分离；前端 cell 有 backend order_rank |
| I-03 | Report canonical hash 不受 request ID、nonce、wall clock 影响 |
| I-04 | backend NormalizedIR 与 public AnalysisSnapshotReport 类型分离；wire 不暴露 raw_text/CounterStrategy/merge recipe/内部实体，SourceView 仅安全文本/token DTO |
| I-05 | Outcome state/diagnostics 只来自 report；Comparison attempt 状态只由 outcome 或 error 二选一推导，无重复可矛盾字段 |
| V-01 | `version_source`、`pack_match`、`compatibility` 三个独立字段/enum，无第二套 resolution truth |
| V-02 | user-declared 3.5.14 只选择候选 pack，不直接 supported；unknown 不套最近 pack |
| V-03 | VersionPack 无 RuleSet/severity/recommendation；新版本使用独立 pack/delta/goldens |
| V-04 | profile level 2、Running/runtime snapshot、unmerged 均传播到 completeness/rule applicability，不冒充最终 merged Profile |
| V-05 | output rows 按 VersionPack 有序 operator recipe 选择/组合（含 sink PushRowNum、Union、broadcast exchange/InstanceNum）；未知 operator 为 unavailable，不默认 sum/non_additive 数值 |
| G-01 | explicit topology 保留准确节点/边/evidence |
| G-02 | verified_derived edge 只在唯一可证时产生并有 versioned derivation rule |
| G-03 | 歧义/失败为 partial/unavailable + unresolved，edges 不构造线性假树 |
| G-04 | 一个 plan_node_id 可对应多个 pipeline operators，不错误去重 |
| G-05 | graph unavailable 时 Operators/Source/Diagnostics 仍可用 |
| G-06 | plan node、native/subordinate operator、fragment/exchange 分层；Text indentation 不作为拓扑证据，跨 fragment edge 必须有明确证据 |
| G-07 | `children/sinkIds/operatorProfiles` 的 source_ordinal 被保留；双子 Join input role 只在有证据时填写，canonical hash 不按 ID 重排语义有序数组 |

## 5. RuleSet 与 Findings

| ID | 通过条件 |
|---|---|
| R-01 | 每条规则有 applicability、typed inputs、formula/threshold source、severity/confidence policy |
| R-02 | 每条计入规则有正/反/边界/缺失/版本/图降级案例 |
| R-03 | severity 与 confidence 独立；不可计算为 not_applicable/suspected；无总体 health score |
| R-04 | Finding 含 evidence、limitations、人工 validation steps 和 rule trace |
| R-05 | OPERATOR_TIME_SHARE 与 3.5.14 官方 numerator/denominator/15/30 display thresholds trace 对齐，不宣称 query health |
| R-06 | SPILL_OBSERVED 只在 exact canonical >0 或有损 observation lower bound >0 时触发；区间含 0 为 suspected，exact 0 不触发，缺失/invalid 不当作 0 |
| R-07 | TIME_SHARE 区间全低/全高/跨15/跨30、分母 exact 0/interval 含0/unknown bounds 的三值判断与 not_applicable goldens 通过 |
| R-08 | Recommendation 包含 action kind、risk、expected direction、validation plan；product_rule 与 starrocks_plan_advisor 来源不可混淆 |
| R-09 | scan/filter/storage 与 exchange/network 若没有 3.5.14 typed evidence + 六类 golden，只能 investigation，不输出具体修改 |

共同门禁 R-01..04 必须全部通过；`OPERATOR_TIME_SHARE` 还必须通过 R-05 + R-07，`SPILL_OBSERVED` 还必须通过 R-06。任一适用门禁失败时从 v0.1 manifest 移除；规则数量不是门禁。

## 6. Compare

| ID | 通过条件 |
|---|---|
| D-01 | baseline/candidate 分别返回 complete/partial/failed attempt，不互相继承版本/adapter 状态 |
| D-02 | delta 区分 compatibility、structure、metrics、findings 和 not_comparable reason |
| D-03 | baseline exact 0 保留 absolute delta，percentage=`undefined_baseline_zero` |
| D-04 | missing/invalid/partial/unavailable 不当作 0，不生成伪 numeric delta |
| D-05 | metric/order rank 均由后端生成，前端不从 display/raw/canonical string 重算 |
| D-06 | baseline interval 含 0 时 percentage=`undefined_baseline_interval_contains_zero`；排除 0 的有界输入只生成 conservative approximate bounds |
| D-07 | registry explicit equivalence、lossy interval、rule/evaluator version change 分别进入 comparable/approximate/algorithm_changed，不做 fuzzy 等价 |
| D-08 | Explain/Explain 仅 plan structure/property delta；Profile/Explain 的 runtime delta=`not_comparable_missing_runtime_profile` |
| D-09 | validation context 对 query digest、version、data window、session、resource group、cluster 分别 matched/mismatched/unknown；非全 matched 不做因果归因 |

## 7. API、安全与资源

## 8. StarRocks 连接、Audit 与只读计划证据

| ID | 通过条件 |
|---|---|
| S-01 | `current_version()` exact 探测 3.5.14；unknown/known-other 只返回 unsupported 并允许断开，不执行版本敏感查询、不套最近 pack；capability 的 available/unavailable/forbidden/unknown 分开 |
| S-02 | credential write-only、最多3连接、idle 15min、close/expiry/restart 清除；response/log/report/browser storage 零命中 password/DSN/host user |
| S-03 | host 只允许 DNS/IP+port、禁 URL/path/socket 和 MySQL multi-statements；远端 TLS verify-full，明文只允许 loopback 一次性 Docker |
| S-04 | Audit query 固定安全列/identifier validation/参数化 filter/时间窗/limit；AuditLoader 与 ProfileList 来源/保留/延迟分开；auto fallback 明示 actual source + degraded reason，显式 Audit 不 fallback |
| S-05 | UUID query ID 拉取 Profile，唯一 Text Adapter/Core 解析；成功一次返回当前 query 的 `AnalysisOutcome`，四项摘要与 Report 一致且可直接打开 Doctor；失败不伪造 `fetched + null`，不返回 raw connector Profile；空结果统一 `profile_unavailable + not_found_or_expired_or_not_profiled`，不得猜唯一原因 |
| S-06 | Plan Advisor 仅 `SHOW` 安全投影，标记 Official/Experimental/FE-local/volatile；product rule 与官方 guide 分源；mutation SQL 全拒绝 |
| S-07 | EXPLAIN 只接受单条 SELECT/WITH，由目标 FE 生成；ExplainSnapshot 记录 version/environment/provenance，estimate 不进入 runtime facts |
| S-08 | 产品没有通用 `/validate`/execute 路由；Runtime Top 只接受单条 SELECT/WITH 并固定 10 秒超时；`EXPLAIN ANALYZE`、INSERT/UPDATE/DELETE/DDL/LOAD/ADMIN/SET/Plan Advisor mutation/multi-statement 在远端调用前稳定拒绝，fake connector 远端调用计数为 0 |
| S-09 | candidate Profile 仅通过“用户在 StarRocks 侧复跑 -> 刷新 Query Browser -> 拉取”获得；Explain 不生成 Profile，Profile/Explain runtime delta 为 `not_comparable_missing_runtime_profile` |
| S-10 | 官方 3.5.14 image index digest、实际平台 manifest、runtime version/build、固定源码 commit、AuditLoader version/SHA、健康与清理回执分别可复核，不互相冒充 |
| S-11 | Docker E2E 的 admin、AuditLoader writer、doctor reader、workload user 分离；产品永不持有 bootstrap/admin/workload 凭据，不自动安装插件/建表 |
| S-12 | 断网/无 Docker 时 Offline Import/Doctor/Compare/Export 全部回归；日志/错误/导出负向扫描无 password/DSN/完整 SQL/Profile/Advisor 原文/绝对路径 |

## 11. v0.1 Candidate GO

只有同时满足以下条件才可从 `NOT_READY` 变为 `v0.1 Candidate`：

1. FR/AC 追踪矩阵与本矩阵所有必须项通过；
2. Parser、IR、Graph、RuleSet、Connector、Analysis/Compare API/Security 和关键 UI 命令可重放；
3. Offline Import -> Doctor -> Recommendation -> Compare/Export 与 Connected Audit/ProfileList -> baseline Profile -> Recommendation -> Explain -> 用户侧受控复跑 -> candidate Profile -> Compare 两条 E2E 均通过；
4. 失败、降级和不支持状态在 UI/API 中真实可见；
5. clean build、锁文件、build hash、SBOM/许可证、支持矩阵、已知问题和删除/回滚回执完整；
6. Docker 3.5.14+AuditLoader 证明隔离环境；无合法真实脱敏用户集群时，生产连接/负载安全保持 `INCONCLUSIVE`。
7. `B-01..B-03` 全部通过，优势声明只覆盖已验收闭环。

`v0.1 Candidate` 不等于 Production。容量、HA、备份恢复、升级回滚、渗透测试和真实集群低侵入证据不在本版本。
